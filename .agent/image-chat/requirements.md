# 需求文档

## 引言
本文档定义 OpenINTJ Agent IDE 的"图片会话"功能需求。该功能允许用户在对话中上传图片，Agent 能够理解图片内容并结合文本进行多模态对话。当前系统仅支持纯文本对话，本次需求旨在扩展为支持图文混合输入，对接腾讯混元 Vision 多模态模型（或在 LKEAP 端点不支持时提供优雅降级）。

**技术背景约束：**
- 当前使用 LKEAP 端点 `https://api.lkeap.cloud.tencent.com/plan/v3`，该端点是否支持 Vision 模型尚不确定
- 如 LKEAP 不支持 Vision，需提供降级方案（提示用户、或切换到支持 Vision 的端点）
- 前端为纯静态页面（无框架），后端为 FastAPI + OpenAI 兼容 SDK

## 需求

### 需求 1：前端图片上传与预览

**用户故事：** 作为一名用户，我希望在对话输入区域能够选择并预览图片，以便将图片作为上下文发送给 Agent。

#### 验收标准
1. WHEN 用户点击输入区域的图片上传按钮 THEN 系统 SHALL 弹出文件选择器，仅允许选择图片文件（jpg、png、gif、webp）。
2. WHEN 用户选择图片后 THEN 系统 SHALL 在输入区域上方显示图片缩略图预览，并提供移除按钮。
3. IF 图片文件大小超过 5MB THEN 系统 SHALL 提示"图片过大，请选择 5MB 以内的图片"并拒绝添加。
4. WHEN 用户点击预览区的移除按钮 THEN 系统 SHALL 移除已选图片并恢复纯文本输入状态。
5. WHEN 用户拖拽图片到对话区域 THEN 系统 SHALL 支持拖拽上传并显示预览（与点击上传行为一致）。
6. WHEN 用户粘贴剪贴板中的图片 THEN 系统 SHALL 支持粘贴上传并显示预览。

### 需求 2：图文混合消息发送与展示

**用户故事：** 作为一名用户，我希望发送包含图片和文字的混合消息，并在对话历史中看到完整的图文内容。

#### 验收标准
1. WHEN 用户附带图片点击发送 THEN 系统 SHALL 将图片转为 Base64 编码，连同文本一起发送到后端 `/api/chat` 接口。
2. WHEN 消息发送成功 THEN 系统 SHALL 在对话历史中以用户消息气泡形式展示图片缩略图和文本内容。
3. IF 仅上传图片而未输入文本 THEN 系统 SHALL 允许发送纯图片消息（文本为空）。
4. WHEN Agent 响应包含对图片的分析 THEN 系统 SHALL 正常展示 Agent 的文本响应（保持现有打字机效果）。

### 需求 3：后端多模态消息处理

**用户故事：** 作为一名开发者，我希望后端 API 能够接收并处理图文混合消息，以便将多模态内容正确传递给 LLM。

#### 验收标准
1. WHEN 后端 `/api/chat` 接口收到包含图片的请求 THEN 系统 SHALL 解析图片数据（Base64），并构建 OpenAI Vision 格式的多模态消息。
2. WHEN 构建多模态消息 THEN 系统 SHALL 将消息 content 字段从字符串格式转换为数组格式，包含 `text` 和 `image_url` 类型的内容块。
3. IF 请求中不包含图片 THEN 系统 SHALL 保持现有纯文本消息格式不变（向后兼容）。
4. WHEN 图片 Base64 数据格式不合法 THEN 系统 SHALL 返回 400 错误并提示"图片数据格式无效"。

### 需求 4：LLM 客户端多模态调用

**用户故事：** 作为一名开发者，我希望 LLM 客户端能够支持多模态消息格式，以便正确调用支持 Vision 的模型。

#### 验收标准
1. WHEN LLM 客户端收到包含图片的消息 THEN 系统 SHALL 自动切换到 Vision 模型（如 `hunyuan-vision`）进行调用。
2. IF 当前 LKEAP 端点不支持 Vision 模型 THEN 系统 SHALL 返回明确的错误提示"当前 API 端点不支持图片理解，请切换到支持 Vision 的端点"，而非静默失败。
3. WHEN LLM 客户端处于 Mock 模式 THEN 系统 SHALL 对图片消息返回模拟的图片描述响应（如"[Mock] 检测到图片输入，模拟图片分析结果..."）。
4. WHEN Vision 模型调用失败 THEN 系统 SHALL 降级为纯文本模式，仅使用文本部分调用标准模型，并在响应中附加提示"[注意：图片分析不可用，仅基于文本内容响应]"。

### 需求 5：上下文引擎与记忆系统扩展

**用户故事：** 作为一名架构师，我希望上下文引擎和记忆系统能够处理多模态内容，以便图片信息能被正确纳入 Agent 的上下文管理。

#### 验收标准
1. WHEN 用户发送图片消息 THEN 上下文引擎 SHALL 将图片信息记录为对话消息的一部分（包含图片标记和估算 token 数）。
2. WHEN 记忆系统存储图片相关对话 THEN 系统 SHALL 仅存储图片的文本描述摘要（由 LLM 生成或标记为"[图片]"），而非原始图片数据，以节省记忆空间。
3. WHEN 上下文压缩（session compaction）触发 THEN 系统 SHALL 将图片消息压缩为文本摘要形式（如"用户发送了一张包含XX内容的图片"）。
4. IF token 预算不足以容纳图片 THEN 系统 SHALL 优先丢弃历史图片数据，保留文本上下文。

### 需求 6：LLM 状态与能力展示

**用户故事：** 作为一名用户，我希望在界面上能看到当前 LLM 是否支持图片理解，以便知道何时可以使用图片功能。

#### 验收标准
1. WHEN 页面加载 THEN 系统 SHALL 检测当前 LLM 是否支持 Vision 能力，并在状态栏显示。
2. IF LLM 不支持 Vision THEN 系统 SHALL 在图片上传按钮上显示禁用状态或提示"当前模型不支持图片"。
3. WHEN LLM 状态 API 返回 Vision 支持信息 THEN 系统 SHALL 在底部状态栏和头部状态区域展示多模态能力标识。
